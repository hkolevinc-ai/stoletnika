# Stoletnika → Temu: версия 1.6

## Стартиране в GitHub

1. Разархивирай пакета и качи съдържанието в основната папка на хранилището, като замениш старите файлове. Включи папките `.github` и `templates`.
2. Отвори **Actions → Stoletnika - Temu → Run workflow**.
3. Остави **mode = full** и стартирай.
4. Изтегли **Artifacts → stoletnika-temu-results**. Попълненият файл е **TEMU_STOLETNIKA.xlsx**.

Качи съдържанието на ZIP, а не самия ZIP. При останали стари workflow файлове избери точно `stoletnika-temu.yml`.

Папка `results` съдържа вече попълнен файл с 742 продукта от реалното HTTP сканиране на 5 октомври 2026 г. Цените са в EUR. Всички 742 продукта имат категория. За 329 продукта е избрана най-близката налична категория, като изборът е отбелязан в `results/review.csv`. Липсващите размери продължават да се отбелязват в отчета.

## Нова логика

Скрейпърът изпраща обикновени HTTPS GET заявки с Python. Извлича публичните структурирани данни на CloudCart (`window.cc_page_data`) и публикуваните продуктови варианти директно от отговора. JavaScript не се изпълнява. Транспортът разпознава и публичните JSON отговори с HTML съдържание.

Chrome, Playwright, nodriver и Xvfb са премахнати от пакета и workflow. Не се инсталират допълнителни библиотеки и не се изискват API ключове или ръчен браузърен експорт. Използва се един постоянен HTTP профил, с пауза между заявките.

RSS източникът на магазина съдържа само 20 записа и затова не се използва като пълен каталог. Скрейпърът обхожда всички страници от трите зададени списъка и извлича пълните продуктови страници за описанията и вариантите.

## Попълване на Temu

Пакетът съдържа оригиналния приложен шаблон. Продуктите се записват от ред 5. Техническите листове, падащите менюта, валидациите и заглавните редове се запазват.

Цената е текущата продажна цена в **EUR**, включително действителното намаление. Редовна цена се добавя само когато е по-висока от текущата. Използват се изображенията на конкретния продукт. SKU и баркодове остават текст; цените и количествата са числови клетки.

Размери, точна наличност и юридически данни се попълват само ако са публикувани или зададени в `config.json`. Липсите се отбелязват в `review.csv`. При липса на точно съвпадение се избира най-близката налична категория според основния продукт, съставките и продуктовата група. Категорията се попълва за всеки продукт. Приблизителните избори се обозначават с `nearest:` в `category_reason` на отчета; имената и съставът на продукта запазват данните от сайта.

## Проверка и изходни файлове

`mode = test` проверява трите списъка и по един продукт от всеки — шест заявки, без Excel. Основният режим `full` сканира целия обхват.

- `TEMU_STOLETNIKA.xlsx` — попълнен оригинален шаблон.
- `discovery.json` и `products.json` — открити и извлечени продукти.
- `review.csv` и `review.json` — липси по редове.
- `summary.json` — бройки, EUR, марки и `full_catalog_scraped`.
- `errors.json` — грешки при извличане или попълване.
- `network_diagnostics.json` — HTTP статус на всяка заявка.

При HTTP 403 или човешка проверка скрейпърът запазва отговора и спира новите заявки. Частичен резултат не се отчита като пълно сканиране. Достъпът от конкретния GitHub runner не може да се потвърди от тази среда; включеният `VALIDATION.json` описва действително изпълнената проверка тук.

## Локално стартиране

Изисква Python 3.12. От основната папка:

```sh
python scrape_stoletnika.py --refresh
```

За кратък тест:

```sh
python scrape_stoletnika.py --refresh --check-access
```

За повторно попълване от вече извлечени данни, без заявка към сайта:

```sh
python scrape_stoletnika.py --offline-json output/products.json --out rebuilt
```

Автоматичните проверки се изпълняват с:

```sh
python -m unittest tests.test_scraper tests.test_http -q
```
